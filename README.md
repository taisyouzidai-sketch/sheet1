# 精算表web

## 本ツールの目的と「最大の工夫・こだわり」

本システムは、手計算では混乱しやすいプレイガイドの複雑な精算額を完全に可視化し、**「事前支払いの売上」と「当日現場にある現金売上」を厳密に仕分けて計算ミスを完全にゼロにすること**を目的としています。
外部のサーバーやデータベースは一切使わず、ブラウザの機能だけで動く軽量なスタンドアロン型システムです。


### 開発のきっかけ：現場で多発する「混ぜる・足し忘れる」の防止
実際の現場では、**「いつもドリンク代の欄についうっかりバッジ代まで合算して入れてしまう」**、あるいは**「ドリンク代とバッジ代をせっかく別々で書けたのに、最後の飲食総合計を出すときにバッジ代を電卓に足し忘れて、レジ金が合わなくなる」**という計算ミスが私個人で起きていました。
このミスを、システムが先回りして自動で仕分け・計算することで、現場の精神的負担をゼロにします。

### 本作独自のハイライト（技術的な見どころ）

#### ① 【最大の工夫】精算表の総チケット代と、当日決済分の動的仕分け
チケット代の入力欄には、事前に支払ったチケット代の金額も含まれます。しかし、レジ締め（現金照合）のフェーズでは当日のレジ内にある現金・PayPayだけを扱わなければなりません。
そこで、**「チケット代の横にあるチェックマーク（現金枠）」がついている行の売上だけを自動で抽出し、現金照合エリアの『チケ』の欄へリアルタイムに流し込むロジック**を実装しました。
これにより、「精算書としてのチケット総売上」を正しく算出しながら、「当日現場で発生した現金・PayPayのチケット売上」だけを完璧に分離してレジ金と照合させることができます。

#### ② 計算式の中身が「細かく目に見える」安心設計
売上の95%から発券手数料等を差し引くなど、電卓では複雑なe+（イープラス）等の精算ルールを完全自動化。計算の途中経過を `<ruby>` タグを用いてリアルタイムに画面へ動的出力するため、なぜその精算額になったのかが一目で検証できます。

#### ③ 物理電卓を机から完全に排除する「Enter連動・拡張計算メモ」
上の「現在・前回」のPayPay引き算枠を使うまでもないシンプルな運用のときや、「総合計からPayPay額をサクッと引いてとりあえず計算したい」という場面を想定し、画面内にEnterキーだけでサクサク操れる計算メモを配置しました。
わざわざ物理電卓に持ち替える手間を無くし、すべての計算をこの画面1枚の中で完結させます。

## 操作性・UX（技術仕様）

### 1. 現場の打鍵速度を高める「入力UX」

- **Enterキーによるフォーカス自動遷移と全選択**
  
  Enterキーだけで次々と項目を自動移動（フォーカス遷移）させ、移動した瞬間に文字を100%全選択（ハイライト）状態に制御（`.select()`）。前のデータを消す手数を省き、テンキー入力だけで瞬時に上書きできます。
  
- **確実な上書きのための「ダブルクリック」推奨設計**
  Enterキーでの移動時は自動で全選択になりますが、マウスで操作する場合は枠を1回クリックするだけだと、前の数字を消す手間が発生します。そのため、確実に100%文字を全選択して瞬時に上書きできるよう、**「Enterキーでの移動」または「枠のダブルクリック」での運用を推奨する設計**に制御しています。
- **スピンボタンの完全抹殺と「半角入力」推奨の理由**
  数字入力枠に勝手に出現するブラウザ標準の「▲▼矢印ボタン」をCSSで完全消去。なお、メインの入力枠に全角で数字を打ち込むと、ブラウザの仕様上、入力途中の数字が見えなくなる現象が発生します（※ただし、直接計算式を入力しているわけではないため最終的な計算自体は成り立ちます）。この視覚的な問題を回避し、最もスムーズに操作するため、**数字は最初から「半角」で入力することを強く推奨する設計**にしています。

### 2. 「見慣れた構図」で迷わせない視覚レイアウト
- **本物の精算表の構図を忠実に再現**
  画面のレイアウトは、現場のスタッフが見慣れている実際の紙の精算表の構図をそのまま再現しています。そのため、無暗にすべてを右寄せにするのではない、精算表本来の並びを活かすことで直感的に迷わず入力できるデザインに仕上げています。（※数値入力や一部の合計額など、重要な金額エリアに絞って右寄せを適用し、縦の桁数を揃えています）

- **ピクセル単位の列幅調整と極小パディング**
  列幅を1マスずつドット単位で鬼調整し、1行の高さを30pxに圧縮。PC環境で全ての重要情報がスクロールなしで1画面に収まりきるグリッド設計です。

- **合計行のフォーカス吸い込み排除**
  チケット合計などの読み取り専用（readonly）の枠に `tabindex="-1"` を指定。Enter連打中にカーソルが合計枠に吸い込まれて打鍵の手が止まるストレスを排除しています。

- **背景色によるビジュアル・ゾーニング**
  データの種類（ドリンク関連とバッジ計算エリアなど）ごとに背景色を分けることで、脳が1秒でデータを識別できるよう工夫し、使いやすさを調整しています。


### 3. キーボードだけで操れる計算メモの制御
- **入力文字に合わせた自動伸縮**: 入力欄の文字数（高さ）に合わせて、表示領域がリアルタイムに縦に自動伸縮（`scrollHeight`連動）。
- **全角入力時の挙動に関する仕様**: 
  計算メモ内では、使い慣れた「×」や「÷」の記号、長音（ー）などのマイナス入力をプログラミング用演算子へと翻訳して処理します。なお、この計算メモ欄で全角数字を使用した場合、入力中の文字は見えますが計算が成り立たなくなるため、**こちらも同様に「半角数字」での入力を必須とする運用設計**にしています。
- **打鍵リズムとの連動**: Enterキー連打で「無限に行が追加されてフォーカスが次へ飛ぶ」機能、および空行でのBackspace連打で「上の行へ戻りながら不要な行を自動消滅させる」高度なキーバインド制御を実装しています。

##  開発環境・仕様

- **開発言語**: HTML5 / CSS3 / JavaScript (Vanilla JS)
- **開発ツール**: VS Code (Visual Studio Code) 
- **開発体制**: GoogleのAIにコードを書いてもらいながら共同開発を行い、システムを完成させました。

### 推奨環境・対応ブラウザ（画面サイズとビジュアルの制限）
- **PC操作に特化した設計（スマホ閲覧時の制限）**
  スマートフォンでも開いて使用すること自体は可能ですが、本システムはPCの物理キーボードによる高速打鍵と、1画面で全ての精算データを見渡せる一覧性を最優先に設計しています。スマホの狭い画面では一覧性が下がり、OSの仕様上Enterキーのサクサク感が損なわれるため、**PC環境での利用を強く推奨**しています。
- **Google Chrome 最適化（マルチブラウザ対応）**
  SafariやEdgeなど、他の主要ブラウザでも問題なくすべての計算ロジックは動作します。ただし、開発時にGoogle Chromeで1px単位のビジュアルやグリッドの確認をしながら制作したため、**Google Chromeで表示した際に最も美しく、最高の見やすさと操作性を発揮します。**（他ブラウザで表示崩れが気になる場合は、URLをChromeに貼り付け直してのご利用をおすすめします）
  
### 【ファイルを1枚にまとめた理由】
本来、Web開発ではファイルを機能ごとに分けるのが一般的ですが、一度完成したコードを後から細かく書き換える予定がないため、GitHubへのアップロードの手間を最小限に抑える目的であえて「HTMLファイル1枚」にすべてを詰め込んだ構成にしています（手軽さを最優先にしました）。
特別な環境準備をしなくても、このファイルをブラウザ（Google Chromeなど）にドラッグ＆ドロップするだけで、その場ですぐ動かせる手軽さを実現しています（※ただこれはめんどくさがりで全然良くない行為です）。
